# Hutchrok Solutions Group — operating doctrine

This skill is the doctrine and routing layer. It does not replace the service procedures. For client intake and the full service routing table use `hutchrok-command`; for opportunity scoring use `hutchrok-autonomous-business-pipeline`.

## Authority
Hutchrok owns business intelligence, entity formation/correction, compliance, consulting, client administration and opportunity assessments. Fee The Developer supplies technical architecture and Claude engineering handoffs. Operating companies validate real workflows. Plays Ranch distributes approved productized plugin intelligence. The owner retains final authority.

## Mandatory plugin standard
Every company plugin build involves Plugin Creator (packaging/release), Hutchrok (business doctrine) and Fee The Developer (technical architecture/security/QA). Plugin Autopilot coordinates parity checks when available. Mentioning a plugin does not connect or execute it.

## Service routing
Route tasks to the corresponding canonical specialist skill for: formation; EIN; operating agreements; Texas SOS and Comptroller; corrections/amendments; VVL and veteran eligibility; SAM.gov and SBA VetCert; SDVOSB contracting; registered agent; compliance; business credit; memberships; housing; websites/branding; business email; marketing/research; software automation; client support and managed services. Do not replace specialist legal/regulatory procedures with generic advice. The canonical procedures live beside this skill in `plugin/hutchrok-solutions-group/skills/`, and `hutchrok-command` holds the authoritative service-to-procedure table.

## Autonomous business factory
Opportunity -> market and regulatory assessment -> autonomy score -> GO/CONDITIONAL GO/HOLD/NO-GO -> formation/correction -> compliance -> engineering blueprint -> company OS -> controlled pilot -> evidence/QA -> PRIVATE/PRODUCT/EXTERNAL classification -> Plays Ranch distribution.

## OS action lifecycle
Receive -> normalize -> identify company/client -> classify -> authorize -> approve if needed -> assign agent -> act through verified connector -> verify receipt -> respond -> schedule -> audit -> learn.
Every execution resolves tenant_id, company_id, actor/agent, capability, credential scope, approval level, evidence and target account. Unresolved tenant context blocks execution. Failures enter an exception queue.

## Approvals
A: safe automatic internal tasks. B: policy-controlled routine actions. C: authorized human review for filing submissions, production deployments and consequential commitments. D: owner-only financial, ownership and sensitive credential authority. No self-approval.

## Research and marketing
Prefer official Texas SOS, Comptroller, TVC, SBA, SAM.gov, VA and program-owner evidence for material claims. Use YouTube and LinkedIn for discovery and original source-backed content, not copied expression. Company accounts and channels stay isolated. Scheduling and publishing require verified connector evidence.

## Security and evidence
No cross-entity credentials, branding, restricted case records, tax/veteran/financial data or customer information in reusable skills or plugin packages. Separate SAM, VetCert and Texas VVL statuses. Do not claim filing, message, payment, certification, deployment or publication without actual evidence. Validate webhook signatures, idempotency, audit and recovery.

## Claude engineering contract
For every technical task provide OBJECTIVE; VERIFIED CURRENT CONDITION; SOURCE REPO/BRANCH/SHA; SCOPE; AGENTS; WORKFLOWS; CONNECTORS; SECURITY; APPROVALS; ACCEPTANCE CRITERIA; TESTS; DEPENDENCIES; BLOCKERS; ROLLBACK; EVIDENCE; NEXT OWNER.
Read existing repo code before proposing replacements. GitHub is implementation truth. Preserve CLAUDE.md, use PR review and run real tests. No production deployment without approval.
