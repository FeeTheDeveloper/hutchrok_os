# Plugin Productization and Plays Ranch Distribution

Treat a company plugin as a productized slice of a legitimate operating company's intelligence, not as the company's complete private operating system.

## Intelligence classes
Classify every candidate capability as PRIVATE, PRODUCT, or EXTERNAL.
- PRIVATE: internal OS logic, credentials, sensitive records, proprietary decision systems, unrestricted admin tools, private customer data.
- PRODUCT: selected knowledge, procedures, analysis, drafting, decision support, or governed workflows intentionally offered to users.
- EXTERNAL: narrowly authorized actions exposed through supported connectors/tools with explicit permissions, tenant isolation, audit, and approval controls.

Default to PRIVATE when classification is unresolved.

## Plays Ranch role
Plays Ranch Programming is initially the publisher, distributor, endorsement, and trust layer for plugins backed by real companies. Do not claim full business autonomy until validated in operation.

A future Plays Ranch verification program should test company identity, capability behavior, permissions, privacy/security boundaries, human-vs-automated disclosures, versioning, release provenance, and quality criteria.

## Registry contract
Track Company -> Plugin -> Capabilities -> Skills -> Supported AI Platforms -> Verification Status -> Version -> Publisher -> Permissions -> Required Connections -> Release Status -> Endorsement Status.

## Productization gate
Require real-company validation, defined intelligence boundary, security review, permission review, QA evidence, release/version record, and owner authorization before distribution.
